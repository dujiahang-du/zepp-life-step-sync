# StepSync · Zepp Life 步数同步管理

Flask + SQLite 的 Zepp Life 账号管理工作台，提供响应式页面、按小时计划、执行状态与记录统计。所有时间按北京时间显示。

## 本机运行

建议使用 Python 3.12（本项目验收环境），需要 Python 3.11 或更新版本。

```powershell
git clone https://github.com/dujiahang-du/zepp-life-step-sync.git
cd zepp-life-step-sync
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Windows 也可在安装依赖后双击 `start.cmd`。打开 <http://127.0.0.1:5002>，注册网站账号，然后添加自己的 Zepp Life 手机号或邮箱账号。网站账号和运动账号是两套独立凭据。

使用 Waitress 单进程运行，默认仅监听本机，关闭进程或电脑休眠期间不会执行计划。不要开启开发重载器或同时运行多份服务。文件锁用于避免同一实例重复启动调度，不是分布式部署方案。

## 功能与交互

- 桌面侧栏、手机导航、空状态引导；所有样式、图标、脚本本地加载。
- 添加账号只验证认证，不提交测试步数；更新密码通过重新授权页面完成。
- 步数范围 0–98,800，最大值必须大于 0；执行时间 0–23 点，不支持跨午夜计划。
- 启用计划后在起止时间内每小时整点执行；步数范围按当前时间递增，同一天不低于本系统已成功提交的最高值。
- 手动提交进入后台队列，页面显示等待、执行中和结果；同一账号防重复执行，30 秒内限制再次提交。
- 账号暂停、编辑和删除；删除前有确认框，删除账号同时移除其记录。
- 按账号显示七日趋势和真实成功比例；记录可按日期、状态筛选和分页。

“已接受”表示 Zepp 接口返回成功，不代表微信或支付宝已经更新。不同账号的授权、绑定关系和第三方协议变化，需要在对应 App 中核对。

### 手动同步为什么可能一直是同一个步数

手动同步与自动同步使用同一套累计目标规则，每次执行会重新生成步数，但不保证每次都增加。设置的最小、最大步数是结束时间时的目标范围，结束时间前会按北京时间折算：当前时刻（小时加分钟比例）除以结束小时，最高按 100% 计算；范围两端乘以该比例后向下取整，再在范围内随机取整数。结束时间为 00:00 时直接使用完整目标范围。开始时间只限制自动执行窗口，不参与这个比例计算；关闭自动同步也不会取消手动同步的时间折算。

最终提交值取“本次生成值”和“本系统今天已成功提交的最高值”中较大的一项，因此生成值较低时会继续提交当天最高值。例如目标 20,000–23,000、结束时间 22:00，在 18:00 生成约 16,363–18,818 步；若当天已成功提交 19,175 步，本次仍提交 19,175。到 22:00 后才使用完整的 20,000–23,000 范围。

若想立即使用完整目标范围，可把结束时间设为当前小时或更早，开始时间不能晚于结束时间，保存后再手动同步。若想生成固定值，可将最小、最大步数设为同一个数；结束时间前仍按时间折算，最终提交值仍不会低于当天已成功值。调整结束时间也会改变自动计划的执行窗口；只需手动操作时先关闭自动同步，完成后按需要恢复原设置。保存设置不会立即提交步数。

排查时先看项目的最新执行记录：若记录中的提交值未增加，应核对目标与时间设置；若项目已接受更高值而微信仍未变化，则继续核对微信端同步，不反复重授权或重复提交。

## 授权与异常恢复

常规同步只复用已有令牌。授权失效后暂停账号，不会使用保存的密码自动重新登录。首次连接和手动重新授权需要确认手机端可能被退出；这项限制由 Zepp 的会话策略决定，无法承诺两个客户端始终同时在线。

提交超时、响应无法解析或提交接口返回服务器错误时，结果标为“待确认”并暂停。先到 Zepp Life 核对结果，再在账号卡片确认恢复；恢复不会补交上次步数，自动同步需要另行启用。队列满导致的计划跳过会留下记录。授权中断、设备待确认、结果待确认和跳过不计入确定结果的接受比例。

## 设备确认与实验性绑定

账号菜单 → **设备管理** → **重新查询设备**。每次提交都会重新查询 Zepp 设备列表；查询失败或没有可确认的设备时停止，不再使用默认设备身份提交。已有手环或手表时直接使用查询到的设备；未识别的设备不会被当成“未绑定”。

仅在设备列表确认为空时，页面显示实验性虚拟绑定入口。勾选说明后，程序先加密保存设备身份和尝试状态，再发送一次绑定请求，并重新查询列表，确认同一设备确实出现。超时、拒绝或回读未匹配时保持暂停，后续只重新查询，不自动重复绑定。重新授权不会删除已保存的设备身份。

设备操作不提交步数，也不自动重新登录；完成后自动计划仍暂停。可返回账号管理手动同步，再核对 Zepp Life 和微信运动。虚拟绑定不是官方支持的功能，不能保证第三方平台接收，也不能解决手机端登录被挤出的问题。不要通过删除并重建账号反复尝试绑定。

## 数据与安全

运行时数据在 `instance/`，不属于公开源码：

- `mimotion.db`：网站用户、加密运动凭据、执行任务及记录。
- `secrets.json`：首次运行生成的随机会话密钥和 Fernet 加密密钥。
- `logs/`、`backups/`：运行日志及升级前 SQLite 快照。

网站密码使用哈希存储；运动密码、令牌和设备身份使用本机随机密钥加密。数据库与密钥必须一起备份，且仅允许可信系统用户读取。密钥丢失会导致已有运动凭据无法解密，不能靠重新生成密钥恢复。旧版明文数据库备份仍可能含敏感信息，应留在本机受控目录。

默认启用 CSRF、防跨用户访问、请求体限制、安全响应头和登录限流。注册默认开放给可访问本机页面的人。若另行部署到网络，需要 HTTPS、反向代理访问控制及适当的运维配置；仓库公开不会自动公开本机服务。

可选环境变量：

| 变量 | 作用 |
| --- | --- |
| `PORT` | 本机端口，默认 5002 |
| `DATABASE_URL` | 数据库连接地址，默认实例目录 SQLite |
| `SECRET_KEY` | 覆盖会话密钥，必须为私密随机值 |
| `ENCRYPTION_KEY` | 覆盖 Fernet 密钥；已有数据须使用原密钥 |
| `SCHEDULER_ENABLED=0` | 关闭自动计划 |
| `ALLOW_REGISTRATION=0` | 关闭网站注册 |
| `COOKIE_SECURE=1` | 仅通过 HTTPS 发送会话 Cookie |

已有 SQLite 数据库启动时增量升级；涉及字段或密码迁移前自动备份。发现重复账号或密钥错误会停止启动。其他数据库的既有表不支持自动迁移。

回退时先停止服务，再恢复升级前源码和匹配的数据库快照；保留当前实例的独立副本。不要只替换数据库而丢失对应加密密钥。

### 真实微信同步验收与使用建议

2026-10-02 收到使用者人工验收反馈：iPhone 场景下，重新登录后，微信运动排行榜已显示当天通过本项目提交的步数。这是单个账号的一次实际结果，由使用者在手机端确认；本项目没有微信排行榜自动回读能力，不能据此保证其他账号或后续每次同步都成功。

- 保留当前可用的登录和绑定状态，常规提交继续复用已有令牌。不要把重新登录作为每次同步的步骤，也不要为排查连续重新授权、重建账号或重复绑定设备。
- 以微信运动排行榜实际显示为最终验收；Zepp Life 展示或接口返回“已接受”只证明各自阶段的结果。若微信暂未更新，先核对手机端状态和日期，不自动重复提交。
- 本次恢复与重新登录在时间上相关，尚未确定具体原因。微信硬件产品登记及电脑蓝牙模拟属于另一条实验路线，不是本项目运行的依赖，也没有完成微信同步验收。
- 更换电脑时重新创建 `.venv`；若需要迁移已有账号，数据库和对应密钥应作为同一套私密数据安全迁移，禁止通过公开仓库传递。GitHub 仅用于同步源码和文档。
